# MarkLeaf 阶段 5 报告

## 范围

阶段 5 完成基础 Markdown 可视化编辑：段落、1 至 6 级标题、粗体、斜体、链接、无序/有序列表、引用、代码块、水平线、撤销/重做、命令状态同步、中文 IME 保护和安全粘贴。

表格、任务列表和图片虽然阶段 0 原型已有基础解析能力，但正式菜单在本阶段保持禁用，可靠编辑与资源处理仍严格留在阶段 6。

## 实现

- 新增原生“水平线”菜单命令，并路由到 Tiptap `setHorizontalRule`。
- 原生菜单的撤销、重做、剪切、复制、段落、标题、粗体、斜体、链接、引用、代码块和列表状态由编辑器实时上报。
- `commandStateChanged` payload 使用严格白名单和完整字段校验，异常或缺字段消息被拒绝。
- 编辑器在 selection、update、文档加载和命令执行后发送轻量状态，不发送文档全文。
- 撤销/重做启用状态来自 ProseMirror 历史；格式和块级菜单显示当前选中状态。
- 原生复制/剪切通过 WebView2 读取当前选择的纯文本，由 WinForms 写入系统剪贴板；剪切再由受控编辑器命令删除选区。
- 原生粘贴读取 Unicode 纯文本，并通过 ProseMirror 的纯文本粘贴路径插入，`<b>` 等内容不会被解释成 HTML。
- 浏览器原生富文本粘贴先净化：移除脚本、样式、iframe、object、embed、SVG、MathML、图片、事件属性、内联样式和危险 URL。
- composition 期间不发送选区、命令状态或全文；仅在 composition 确实产生编辑时于结束后合并增加一次 revision。
- 正文继续使用英文 Times New Roman、中文宋体-简，代码字体保持不变；新增轻量水平线样式。
- 链接命令仅接受 `http`、`https` 和 `mailto`。
- 未知 directive 风格文本的黄金测试确认不会静默删除可见内容；字符级或完整语法级保真仍不承诺。

## 人工验收建议

1. 使用微软拼音连续输入中文、全角标点、emoji，并测试日文/韩文输入法（若已安装）。
2. 选择中文或中英混排文本，检查粗体、斜体、链接以及菜单勾选状态。
3. 测试 1 至 6 级标题、正文、引用、代码块、无序/有序列表和水平线。
4. 连续执行多步编辑，再多次撤销与重做，检查菜单启用状态和内容顺序。
5. 跨多个段落选择后执行引用、复制、剪切和粘贴。
6. 从网页、Word、纯文本编辑器复制带格式内容，确认安全格式可保留且脚本/图片不会混入。
7. 保存后重新打开文档，确认基础语法达到语义保真。

## 已知边界

- 不承诺 Setext 标题、列表标记、空行等字符级保留；阶段 4 已确保未编辑文件不会被重写。
- 未知复杂扩展语法仍可能被 Markdown 解析器规范化，阶段 8 的源码模式是最终兜底。
- 图片粘贴当前不进入文档；图片资源复制、草稿暂存和迁移属于阶段 6。
- 查找替换、源码模式和多文档属于阶段 8。

## 人工验收反馈修复

- 修复无选区时“插入链接”看似无反应：现在直接插入以 URL 为可见文字的链接；有选区时仍将选中文字设为链接。
- 编辑区点击 `http`、`https` 或 `mailto` 链接时，经严格协议校验后交给 Windows 默认浏览器或邮件程序打开；危险协议在前端和宿主两层拒绝。
- 修复跨文件撤销：每次新建、打开或重新加载文档都销毁旧 Tiptap 实例并重建，使 ProseMirror 历史插件从空状态开始。
- 新增回归测试，确认重建后的文档 `CanUndo=false`，执行撤销不会恢复前一个文件内容。
