# MarkLeaf 阶段 0 Markdown 往返能力报告

## 编辑器内核

原型使用 Tiptap 3.29.2。Tiptap 基于 ProseMirror，并提供 Markdown 解析和序列化、
GFM 表格、任务列表、撤销历史和成熟的浏览器输入事务模型。所有包均由 Vite 打包
为本地静态资源，通过 WebView2 虚拟主机 `https://editor.local/` 加载。

## 已验证能力

- 标题、段落、粗体、斜体、删除线和行内代码。
- 链接、相对图片路径和图片标题。
- 有序/无序嵌套列表、任务列表和引用块。
- GFM 表格及对齐标记。
- 带语言标识的围栏代码块和水平线。
- 中文标点、emoji、转义字符。
- ProseMirror 插入、撤销和重做。
- composition start/end 事件可到达编辑区，宿主在 composition 期间不请求全文快照。
- WinForms/WebView2 真实集成：加载样例、编辑、撤销、重做、请求最新 revision
  快照并导出 UTF-8 Markdown。

## 已观察到的规范化

这些变化保持语义，但不保持原始字符：

- Setext 标题会序列化为 ATX 标题。
- 使用 `*` 的无序列表会规范化为 `-`。
- GFM 表格会重新计算列宽并补齐空格。
- 块之间的空行数量可能规范化。

因此阶段 0 结论是：MVP 语义保真可行，但不能承诺字符级或完整语法级保真。
正式实现必须遵守“未修改时不重新序列化覆盖原文件”的原则。

## 尚未可靠验证

- 真实 Microsoft 拼音、第三方中文输入法、日文和韩文候选窗交互。当前隔离会话
  无法读取有效输入法 TIP 列表，因此仅完成 composition 事件自动测试。
- 未知扩展块和任意 HTML 的无损保留。Tiptap Markdown 序列化器可能规范化或
  丢弃未注册语法；正式 MVP 需要原始块策略或源码模式兜底。
- 1 MB/5 MB 大文档性能与长时间编辑稳定性。
- 表格复杂编辑、跨块选区和大量文本粘贴。

## 风险结论

Tiptap/ProseMirror 适合作为 MarkLeaf 编辑内核继续评估。最高风险仍然是未知语法
保留、宿主与编辑器 revision 竞态，以及真实 IME 在复杂事务中的行为。这些风险
不阻止进入阶段 1，但必须在阶段 4 至 6 前形成更完整的黄金样例与人工 IME 测试。
