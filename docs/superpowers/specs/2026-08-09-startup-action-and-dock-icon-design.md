# MarkLeaf macOS 启动操作与 Dock 图标优化设计

## 背景

偏好设置中的“启动操作”在恢复上次工作区或文件时会静默失效。现场日志显示，应用连续两次尝试打开已被删除的 `/tmp/markleaf_pdf_test.md`，随后退回默认页面。当前实现直接读取 `lastFolder` 和 `lastFile` 并执行 I/O，没有在执行前校验路径，也没有把“无效恢复目标”转换为明确的降级计划。自动化验证还与用户配置共用设置目录，因而可能污染真实的最近工作区和文件记录。

当前 Dock 图标的主体比例已经接近 macOS 图标规范，但缺少圆角底板外侧的接触阴影与扩散阴影。与系统“备忘录”和“文本编辑”图标按相同尺寸测量后，MarkLeaf 的高不透明边界占画布 84.9%，系统参考约 82.0%；MarkLeaf 的不透明面积约 68.9%，系统参考约 62.0%。用户确认采用 S2 尺寸与 B2 阴影：主体线性缩小至当前尺寸的 96%，并使用克制的双层阴影。

## 目标

- 三种启动操作在路径有效、部分失效和全部失效时都有确定行为。
- Finder 或命令行显式传入的文件始终优先于偏好设置中的启动操作。
- “新建文档”打开真正的空白文档，不再加载原型示例 Markdown。
- 无效的上次路径不会弹出阻塞式错误，也不会导致重复失败。
- 自动化验证不再写入用户真实设置。
- Dock 图标在系统常见尺寸下与相邻 App 的视觉体量一致，并保留现有纸张纹理与 M 标识。

## 非目标

- 不实现多窗口、多标签或多文件会话恢复。
- 不改变最近文件、最近文件夹菜单的产品语义。
- 不重新设计图标主体、颜色、字形或纸张纹理。
- 不引入运行时图像处理依赖。

## 方案选择

采用“纯启动决策器 + 薄执行层”。相比只在现有分支中补 `fileExists` 判断，该方案能独立测试所有状态组合；相比完整会话恢复系统，它保持现有单窗口模型，不扩大产品范围。

图标采用已确认的 S2 + B2，并把结果烘焙进最终 1024×1024 PNG。构建流程继续从确定的主图生成 `.icns`，不在每次构建时动态计算阴影。

## 启动架构

新增一个不依赖 AppKit 的启动决策单元。输入包括：

- 用户选择的 `StartupAction`；
- `lastFolder` 和 `lastFile`；
- 显式传入的初始文件路径；
- 可注入的路径有效性检查。

输出为单一 `StartupPlan`：

- `openExplicitFile(path)`；
- `newDocument`；
- `openWorkspace(path)`；
- `openFile(path)`；
- `openWorkspaceAndFile(workspace, file)`。

决策优先级如下：

1. Finder、文件关联或命令行显式传入的文件；
2. 偏好设置中的启动操作；
3. 当所需路径不可用时，新建空白文档。

三种设置的行为：

- `newDocument`：生成 `newDocument`。
- `openLastWorkspace`：有效目录生成 `openWorkspace`；否则生成 `newDocument`。
- `openLastWorkspaceAndFiles`：目录和文件都有效时生成 `openWorkspaceAndFile`；只有目录有效时生成 `openWorkspace`；只有文件有效时生成 `openFile`；两者均无效时生成 `newDocument`。

`AppWindowManager` 继续保证启动计划只执行一次，但不再自行决定恢复策略。它只解释 `StartupPlan` 并调用主会话。`EditorSession` 的初始加载流程在 Web 编辑器就绪后取得并执行计划，执行 `newDocument` 时调用现有空白文档入口。

## 设置隔离

`SettingsService` 通过环境变量 `MARKLEAF_APP_SUPPORT_DIR` 指定隔离的 Application Support 根目录。未设置该变量时，生产环境仍使用 `~/Library/Application Support/MarkLeaf`；自动化测试和诊断启动必须把该变量设为新建的临时目录。测试目录必须在测试结束后清理，且不能回退写入生产设置。

该隔离只改变设置与缓存的落盘位置，不改变正式用户的配置格式。现有 `settings.json` 无需迁移。

## 错误处理

- 决策阶段发现路径无效时不调用 `openDocument` 或 `loadWorkspace`，因此不会触发启动时的阻塞式错误框。
- 无效路径写入诊断日志，日志包含所选启动操作和降级结果。
- 界面加载完成后用非阻塞状态文字说明“上次文件不可用，已新建文档”等结果。
- 不自动删除 `lastFile` 或 `lastFolder`，避免外置磁盘暂时离线时永久丢失恢复记录。
- 显式打开的文件如果读取失败，继续沿用现有错误提示，因为这是用户主动操作而非后台恢复。

## Dock 图标规格

- 画布：1024×1024，透明背景。
- 主体：以画布中心为锚点，将当前完整图稿线性缩放至 96%。
- 阴影：位于主体下方的双层柔和阴影。按 70px Dock 显示尺寸校准，接触层等效为 `y=1px / blur=1px / opacity=14%`，扩散层等效为 `y=5px / blur=7px / opacity=9%`；1024px 主图按相同比例处理。第一层只稳定边缘，第二层只提供低不透明度扩散，不形成明显黑边。
- 保持不变：圆角形状、纸张纹理、横线、M 字形、色彩与主体重心。
- 目标高不透明边界：约 81%–82%，与系统参考图标约 82% 对齐。
- 阴影只能改善边缘分离感，不能成为第一眼可察觉的独立视觉元素。

最终资源仍保存为 `macos/App.png`，由现有 `prepare_resources.sh` 生成 `AppIcon.icns`。源图的历史版本由 Git 保留，不增加新的构建时图像依赖。

## 测试策略

### 启动决策单元测试

- `newDocument` 始终返回空白文档计划。
- 显式文件存在时覆盖三种启动设置。
- `openLastWorkspace` 覆盖有效与无效目录。
- `openLastWorkspaceAndFiles` 覆盖目录/文件的四种有效性组合。
- 路径检查使用注入闭包或临时目录，不依赖用户机器上的真实历史。

### 设置隔离测试

- 测试设置写入临时 Application Support 目录。
- 启动诊断前后，真实 `settings.json` 的内容摘要与修改时间保持不变。

### 图标验证

- PNG 为 1024×1024 RGBA，四角透明。
- 在 alpha 阈值下测量主体边界，确认高不透明边界位于 81%–82% 目标范围。
- 渲染 16、32、64、128 和 256px，检查 M 字清晰度、阴影裁切和圆角边缘。
- 重新生成 `.icns`、构建并安装 App，刷新 Dock 图标缓存后与系统参考图标并排确认。

### 完整验证

- 运行新增 macOS 测试。
- 运行 Swift 构建与现有资源准备脚本。
- 使用隔离设置分别启动三种启动操作，并核对实际工作区、文档和状态文字。
- 确认 Finder 显式打开文档不受启动设置影响。

## 交付结果

- 启动行为不再受失效临时路径影响，三种偏好均有可解释、可测试的结果。
- 自动化验证不会再次污染用户的 `lastFile` 或 `lastFolder`。
- Dock 图标采用 S2 视觉体量和 B2 柔和阴影，在浅色和深色 Dock 上都保持自然边缘层次。
