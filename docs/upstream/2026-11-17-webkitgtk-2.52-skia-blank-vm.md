### Summary
WebKitGTK 2.52.x (Skia-based rendering) renders completely blank/white pages in virtualized GPU-less environments (VMware SVGA II), even though page JS executes normally and script messages flow correctly. The same setup works when downgrading expectations — every documented workaround environment variable fails to restore output.

### Environment
- WebKitGTK: 2.52.6 (libwebkit2gtk-4.1-0, Ubuntu 26.04 "resolute", also observed on 2.52.0)
- Kernel: 7.0.0-43-generic, x86_64
- VM: VMware SVGA II adapter (vmwgfx DRM), 3D acceleration both enabled and disabled — white in both cases
- Session: GNOME Wayland (mutter + Xwayland); app tested with both native Wayland and GDK_BACKEND=x11
- Also reproduced inside Xvfb (:99, 1280x800x24) with LIBGL_ALWAYS_SOFTWARE=1 — rules out mutter/compositor

### Minimal reproduction
Load `data:text/html,<html><body style="background:red"><h1>TEST</h1></body></html>` in a WebView:
- `load-changed` reaches `WEBKIT_LOAD_FINISHED`
- `webkit_web_view_get_snapshot` (SnapshotRegion::Visible) returns a texture that is 100% white pixels (should be 100% red)
- The page's JavaScript runs: `window.webkit.messageHandlers` script messages arrive, DOM content is built (verified via protocol messages reporting document text length)

The window shows only the GTK chrome; the WebView area is white.

### Workarounds attempted (none restore output)
- `WEBKIT_DISABLE_DMABUF_RENDERER=1`
- `WEBKIT_DISABLE_COMPOSITING_MODE=1`
- `WEBKIT_SKIA_ENABLE_CPU_RENDERING=1`
- `WEBKIT_DMABUF_RENDERER_FORCE_SHM=1`
- `WEBKIT_DMABUF_RENDERER_DISABLE_GBM=1`
- `WEBKIT_FORCE_COMPOSITING_MODE=1`
- `LIBGL_ALWAYS_SOFTWARE=1` (forces llvmpipe; verified EGL/GL does initialize with software path)
- `GSK_RENDERER=cairo` for the embedding GTK app
- Combinations of the above, under both X11 and Wayland backends, with and without bwrap sandbox GPU device passthrough (render nodes are visible to WebKitWebProcess)

### Additional observations
- WebKitWebProcess stays alive (no crash loop), idle CPU ~0%
- vmwgfx exposes /dev/dri/renderD128; with 3D enabled the kernel reports SM_5_1X shader model support
- Mesa svga driver logs `egl: failed to create dri2 screen` when 3D is disabled; with 3D enabled GL initializes but output is still white
- Downgrading to the 2.4x series (pre-Skia) is the only known recovery

### Possibly related
- Bug 323049 (Skia GrResourceCache GPU resource corruption)
- Community reports of WebKitGTK 2.52 blank rendering on NVIDIA/Wayland (tinyjsapp#78, xfce-winxp-tc#567, OrcaSlicer#15996) — those involve discrete GPUs; this report shows the failure also occurs with a virtual GPU (vmwgfx) and pure software paths, i.e. the failure mode is broader than driver-specific dmabuf handling.

### Expected result
Pages should render (at minimum via software/CPU path) in VMs without functional hardware acceleration.

### Actual result
Uniform white output for all content, while scripting, layout and messaging continue to work.
