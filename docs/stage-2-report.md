# 阶段 2：原生 HMENU 与统一命令系统

## 已完成

- 通过 user32 P/Invoke 创建系统绘制的 Win32 `HMENU`，未使用 WinForms `MenuStrip`。
- 创建文件、编辑、段落、视图和帮助五组菜单，包含访问键、快捷键文本、分隔线和子菜单。
- 建立统一 `AppCommand` 枚举、快捷键目录、命令状态解析器和命令路由器。
- 使用 `WM_COMMAND` 路由菜单命令；`ProcessCmdKey` 将快捷键路由到同一命令系统。
- 在 `WM_INITMENU` 和 `WM_INITMENUPOPUP` 时更新启用、禁用和勾选状态。
- 实现工作区侧栏、文档大纲、F11 专注模式、快捷键帮助、关于和退出命令。
- 文件、编辑与段落业务尚未接入文档或 WebView2，因此保持可见但禁用，避免虚假功能。
- 在窗体句柄创建时附加菜单，在句柄销毁和窗体释放时解绑并销毁菜单句柄。
- 菜单不使用图片或图标；阶段 2 不需要新增资源，后续资源位置继续使用现有占位清单。

## 主要文件

- `src/MarkLeaf.App/Commands/AppCommand.cs`：统一命令标识与状态上下文。
- `src/MarkLeaf.App/Commands/CommandCatalog.cs`：快捷键和命令 ID 映射。
- `src/MarkLeaf.App/Commands/CommandStateResolver.cs`：动态启用和勾选状态。
- `src/MarkLeaf.App/Commands/CommandRouter.cs`：命令入口和防重复执行逻辑。
- `src/MarkLeaf.App/Native/NativeMethods.cs`：最小 user32 P/Invoke 集合。
- `src/MarkLeaf.App/Native/NativeMenuService.cs`：菜单构建、附加、刷新和释放。
- `src/MarkLeaf.App/UI/MainForm.cs`：`WM_COMMAND`、快捷键和宿主命令处理。
