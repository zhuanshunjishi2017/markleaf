# TCR-001：文字解析修复与基础格式命令

## 背景和必要性

用户在 VS Code 渲染视图中发现 `C++ memory ... C++17` 变成 `Cmemory ... C17`。
共享 Underline tokenizer 把两组加号配成下划线并裁剪中间空白，现有测试未覆盖该输入。
本次还接入原有文字格式、段落和提示框命令，需要验证真实 Webview 入口对选区和只读状态的处理。

## 测试框架与变更

沿用 `packages/editor-web` 的 Vitest + jsdom，不引入新框架。

- 新增 `tests/editor-underline.test.ts`：通过实际 `createEditor`、编辑命令、`getMarkdown` 和再次加载，验证普通加号、C++ 版本号、递增运算符、空白、旧下划线语法、行内代码、代码块和手动下划线。验证解析树、文字、序列化结果及撤销重做；不只测试正则表达式。
- 扩展 `tests/vscode-editor.test.ts`：实际加载 Webview 入口，点击下划线/高亮按钮，验证状态、阅读模式、宿主菜单返回时恢复原选区，以及文档改变后拒绝旧操作。
- jsdom 不提供文本布局；该集成用例通过 ProseMirror 的 `handleScrollToSelection` 隔离滚动几何，不替代编辑、序列化或同步实现，也不据此声称界面滚动正确。
- 继续运行现有 `vscode-sync.test.ts`，验证打开、阅读、组合输入、确认、冲突、源码更新和撤销消息链。没有修改其断言。

## 实际结果

- 修复前已复现用户样例；普通加号和手动给 C++ 加下划线的用例失败。
- 聚焦三组测试：19 + 6 + 19 = 44 个用例全部通过。
- 完整前端测试：357 个用例，346 通过、11 失败；失败用例名称与先前在原始源码上保存的基线一致，没有新增失败。
- 原生前端构建、VS Code 扩展构建均通过；已生成 `artifacts/markleaf-vscode-0.1.1.vsix`（约 1.66 MiB）。构建仍有既有的大 chunk 提示，没有改变警告阈值。
- 没有操作用户的 VS Code 窗口，也没有修改用户用于复现的 Markdown 文档。

完整测试仍有既有的格式刷事件、段落操作柄、公式和 Mermaid 相关失败；不通过删除或放宽断言制造全绿。接入这些功能组时应分别诊断。

## 界面待验收项

安装 0.1.1 后检查原文中 C++ 的显示；使用 U/H 和格式菜单操作选区、段落及列表；检查阅读模式、保存与 Ctrl/Cmd+Shift+V 切换。实际键盘、中文输入法、右键菜单位置和布局验收由用户完成。
