# MarkLeaf for VS Code

[简体中文](../README.md) | [English](./README.en.md) | [繁體中文](./README.zh-TW.md)

MarkLeaf の Tiptap/ProseMirror 編集コア、KaTeX、Mermaid、組版スタイルを使い、VS Code 内で Markdown を閲覧・ビジュアル編集できます。TypeScript 製の拡張機能は VS Code の API と Webview を利用し、独立した Electron 依存関係やデスクトップシェルを追加しません。

現在のバージョン **0.2.6** は 36 項目の設定と 67 項目の設定可能な書式操作を提供します。書式のコピー、表、脚注、数式・図、画像、検索・置換、アウトライン、表示設定に対応します。PDF、HTML、PNG/JPG 画像、プレビュー、印刷に対応しました。

ツールバーメニューは、外側のクリック、Escape、別メニューへの切り替え、拡張機能からのフォーカス移動で閉じます。数式と Mermaid のソースパネルは明暗テーマに対応した不透明な背景を持ち、対応する内容の下に開いて文書と一緒に画面外へスクロールします。空き領域に応じた上下の反転や、ウィンドウ下端への固定は行いません。数式記号パネルは利用可能な領域に合わせてレイアウトを調整します。

プロジェクトと拡張機能の README は 4 言語で提供します。UI の翻訳範囲は「組版と設定」を参照してください。


## エクスポート・プレビュー・印刷

ツールバーの出力メニュー、またはコマンドパレットの **MarkLeaf: 文書 / PDF / HTML / 画像をエクスポート・印刷** を使用します。閲覧モードでも利用できます。「前回の設定でエクスポート」は最後に保存が成功した設定を使い、出力先を再選択します。

- **PDF**：テキストを選択できるページ形式です。A4/A5/Letter/Legal、横向き、四辺の余白、プレーンテキストのヘッダー・フッター、ページ番号を設定できます。収まる表や見出しは同じページに保持できますが、大きな表は改ページされます。
- **HTML**：組版 CSS、描画済みの数式と Mermaid、KaTeX フォント、埋め込み画像を含む単独の文書です。ファイル生成にブラウザーは不要です。Web リンクのリンク先は変わりません。
- **PNG/JPG**：本文幅、1–3 倍の解像度、画像の最大出力高さ、JPEG 品質を選択できます。長い文書は `name-01.png` などの連番に分割し、既存の分割ファイルを上書きする際は確認します。
- **プレビュー**：独立した Chrome/Edge ウィンドウで生成済み PDF・画像、または HTML 全体を表示します。閉じると戻ります。VS Code の進捗通知からキャンセルもできます。
- **印刷**：Chrome/Edge の印刷ダイアログでプリンターを選び、印刷を確定します。用紙・余白・背景はダイアログでも変更できます。ダイアログの終了はプリンターの実際の完了を保証しません。ページごとのヘッダー・フッターには新しい Chromium のページ組版機能を使うため、現在の安定版を推奨します。

出力の既定は `minimal`（Web · 極簡）と明るい配色です。9 種の組版と 19 種の配色を選べます。エディターの配色は引き続き VS Code に従い、出力設定では編集設定を変更しません。設定済みの本文フォントと中西文間隔を使い、カスタム CSS ファイルと編集画面の倍率は出力に適用しません。

PDF・画像・プレビュー・印刷にはインストール済みの **Chrome/Edge** を使い、ブラウザーを同梱・ダウンロードしません。見つからない場合は実行ファイルを選択するか、**MarkLeaf: Export Browser Path**（`markleaf.exportBrowserPath`、マシン設定）を指定してください。macOS の例：`/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`。既存セッションには接続せず、一時プロファイルを処理完了・キャンセル時に解放します。

同期完了後に VS Code `TextDocument` のスナップショットを取得し、Markdown の保存・変更はしません。未同期の競合、画像読み取り、数式・図の解析に失敗した場合は停止し、元のエラーを表示します。ローカル・ワークスペース・HTTP/HTTPS の画像を文書 URI から読み込んで埋め込みます（1 枚 16 MiB まで）。ネットワーク画像はアクセス可能である必要があります。本文フォントはシステムのフォントを使い、KaTeX フォントのみ埋め込みます。中断時に書き込み済みの分割ファイルは結果に表示します。

リモート拡張ホストでは、そのホストのファイルシステムとインストール済みブラウザーを使ってファイルを出力できます。対話プレビューと印刷はローカルのデスクトップ VS Code に限定します。SSH/WSL では出力後にローカルで開いてください。Windows/Linux/リモート環境と実際の印刷機器での検証は別途必要です。


## インストールと文書の表示

ローカルで `artifacts/markleaf-vscode-0.2.6.vsix` を生成し、VS Code の **Install from VSIX…** でインストールします。リポジトリのルートから次のコマンドも使えます。

```bash
code --install-extension artifacts/markleaf-vscode-0.2.6.vsix
```

有効化後、新しく開く `.md` と `.markdown` は既定で MarkLeaf のレンダリング表示になります。既存のソースタブは **Reopen Editor With… → MarkLeaf** または **Ctrl/Cmd+Shift+V** で切り替えます。エクスプローラーの **MarkLeaf: Open Markdown** からも開けます。

VSIX のアップグレード後は文書を保存し、**Developer: Reload Window** でウィンドウ全体を再読み込みしてください。設定ページに古い項目しかない場合や、`markleaf.shortcuts` が未登録と表示される場合も同様です。拡張機能ホストだけを再起動すると、古い設定登録情報が残る場合があります。

MarkLeaf は既定のカスタムエディタとして登録されます。Markdown に別の既定エディタを指定済みの場合や、複数の拡張機能が競合する場合は **Reopen Editor With… → Configure default editor for… → MarkLeaf** を選択してください。同じ場所で **Text Editor** を選ぶとソース表示に戻せます。既存の VS Code エディタ関連付けが優先されます。

### Git の差分表示

VS Code 1.120 以降では、`.md` と `.markdown` の作業ツリー、ステージ済みの変更、コミット履歴の比較に、標準のソース差分エディタを既定で使用します。行番号、追加・削除の強調表示、差分への移動を利用できます。通常のファイルは引き続き MarkLeaf で開き、閲覧・編集できます。

拡張機能は `workbench.diffEditorAssociations` の既定値を提供し、ユーザー設定には書き込みません。既存のユーザー・ワークスペース設定が優先されます。Markdown の差分エディタを明示的に設定済みの場合は、この設定の `*.md` と `*.markdown` を `default` に変更してください。更新後は **Developer: Reload Window** を実行し、既存の差分タブを閉じて開き直してください。古い VS Code はこの自動関連付けに対応していないため、差分タブの **Reopen Editor With… → Text Editor** を使うか、VS Code を更新してください。

## 編集と閲覧

| 機能 | 操作と動作 |

| 文字・段落 | ツールバーと「格式…」（書式）から、太字、斜体、下線、取り消し線、ハイライト、インラインコード、書式解除、H1–H6、見出しレベル変更、前後への段落挿入、複製・削除、リストのインデント、5 種類の GitHub アラートを操作できます。操作名で検索できます。 |
| 書式のコピー・段落ハンドル | 書式付きの文字を選択し、書式コピーを有効にして対象をドラッグ選択します。1 回適用すると終了し、Escape でキャンセルできます。段落左側のハンドルは編集内容の外にあり、その段落のメニューを開きます。 |
| 表 | 行列数を指定して挿入、行列の追加・削除、列の配置、キャプションの設定・解除、表の削除ができます。カーソル位置に応じて操作が表示されます。 |
| 数式・Mermaid | インライン数式・独立数式の挿入、番号設定、種類の切り替え、削除に対応します。数式や図をダブルクリックすると、数式記号入力補助を含む共有ソースコントロールが開きます。Mermaid コードの描画・編集・再描画にも対応します。 |
| 脚注・メタデータ | 脚注挿入、ラベル変更、参照へ戻る、参照解除、定義削除、YAML Front Matter の表示・挿入ができます。既存の定義や参照で使われるラベルは重複使用できません。 |
| コード | コードブロックの言語選択、コピー、ブロックからの退出、構文強調の切り替えに対応します。 |
| クリップボード | 「编辑」（編集）で Markdown・プレーンテキスト・HTML としてコピーできます。通常のコピーは選択テキストと HTML を提供し、プレーンテキスト貼り付けは Markdown/HTML 記号をそのまま挿入します。 |
| 検索・置換 | レンダリングされた本文を、大文字小文字・単語単位で検索し、前後の結果へ移動、1 件または全件置換できます。閲覧モードでも検索できますが、置換には編集モードが必要です。 |
| アウトライン・閲覧 | 「视图」（表示）で H1–H6 アウトライン、段落フォーカス、タイプライター式スクロール、拡大率、組版、配色を設定できます。ステータスバーに文字数、選択文字数、現在のブロックと位置を表示し、ホバーで詳細を確認できます。 |

**阅读 / 编辑**（閲覧／編集）ボタンでモードを切り替えます。文書を開く、検索する、モードや表示設定を変える操作では Markdown を書き戻しません。閲覧モードではコピー、検索、リンク、アウトライン移動が可能で、内容変更は編集モードのみで行えます。

書式メニュー、画像選択、入力ダイアログを開いた時点の選択範囲が保持されます。待機中に文書が変わった場合は選択し直してください。画像の保存後に選択範囲が失効した場合、メッセージに画像パスを残すので別の位置に挿入できます。

閲覧モードではリンクをクリックし、編集モードでは **Ctrl+クリック**（macOS は **Cmd+クリック**）で開きます。Web、本機のファイル、文書内の見出しに対応します。

## 画像リソース

- 「图片」（画像）ボタンで複数ファイルを選択できます。「编辑 → 图片地址」で相対パスや Web URL を挿入できます。PNG、JPEG、GIF、WebP、SVG、BMP、AVIF に対応します。
- 貼り付け・ドロップした画像は文書の隣の `assets` フォルダに保存し、Markdown 参照を挿入します。1 枚あたり上限 16 MiB です。未保存文書では最初のワークスペースフォルダを基準にし、ワークスペースがなければ先に文書を保存する必要があります。
- ファイル選択では既定で画像をリソースフォルダへコピーします。`markleaf.fileImageHandling` で元ファイルの参照に変更できます。保存先、相対パス、`./` 接頭辞を設定でき、既存画像を上書きしない名前を生成します。
- 画像を選び「编辑 → 当前图片操作」から置換、キャプション編集、回転、幅の変更、名前を付けて保存ができます。閲覧モードでは画像の保存のみ可能です。
- 表示には VS Code リソース URL を使い、Markdown には元のパスを保持します。ワークスペース外の画像は格納先ディレクトリから読み込みます。リモートファイルは VS Code のファイルシステム API を使います。

## ショートカットと文書同期

| 操作 | Windows / Linux | macOS |
| --- | --- | --- |
| ソース／レンダリング表示切り替え | `Ctrl+Shift+V` | `Cmd+Shift+V` |
| 本文検索 | `Ctrl+F` | `Cmd+F` |
| 本文置換 | `Ctrl+H` | `Cmd+Alt+F` |
| プレーンテキスト貼り付け | `Ctrl+Alt+V` | `Cmd+Alt+V` |
| 保存 | `Ctrl+S` | `Cmd+S` |
| 元に戻す／やり直し | `Ctrl+Z` / `Ctrl+Shift+Z` | `Cmd+Z` / `Cmd+Shift+Z` |

検索欄では Enter / Shift+Enter で次／前の結果に移動し、Escape で閉じます。Ctrl+マウスホイールで文書の拡大率を変更できます。VS Code の **Keyboard Shortcuts** で MarkLeaf を検索すると、表示切り替え、検索、置換、プレーンテキスト貼り付けを変更できます。表示切り替えはソース側とレンダリング側に別の規則があるため、両方を変更してください。レンダリング側のキーには MarkLeaf のフォーカスが必要で、プレーンテキスト貼り付けは検索欄や数式ソース入力を上書きしません。見出し・文字書式の既定キーは共有編集コアに従い、MarkLeaf の設定で変更できます。Markdown 編集時のソース切り替えは標準プレビューのキーを使用しますが、標準プレビューコマンドはコマンドパレットから引き続き実行できます。

### 書式操作のキー設定

**视图 → 快捷键…**（表示 → ショートカット）、コマンド **MarkLeaf: Configure Shortcuts / 快捷键设置**、または組版・設定の選択画面から開きます。すべての書式操作を検索し、キーを記録・解除・既定値に戻せます。「保存键位」（キーを保存）で即時反映され、メニューとツールバーの表示も更新されます。

インライン数式、独立数式、Mermaid の挿入は既定で未割り当てです。数式挿入にキーを割り当てると、本文カーソル位置へ挿入して既存のソース・記号補助を開きます。表の行列数や脚注など、引数が必要な操作は既存の入力ダイアログを使います。

VS Code 設定の **Markleaf: Shortcuts** は同じ設定を保存します。設定 JSON の例：

```json
"markleaf.shortcuts": {
  "insertMathInline": "Mod+Alt+M",
  "insertMathBlock": "Mod+Alt+Shift+M",
  "toggleBold": "Mod+Alt+B",
  "toggleHighlight": ""
}
```

- `Mod` は macOS では Cmd、Windows/Linux では Ctrl です。`Ctrl`、`Cmd`、`Alt`、`Shift` を明示することもできます。英数字は物理キー位置を使い、macOS Option が生成する記号の影響を受けません。
- A–Z、0–9、F1–F24 の単一の組み合わせに対応します。この設定では連続キー操作や句読点キーは使えません。英数字には Ctrl、Cmd、Alt のいずれかが必要です。
- 未設定の操作は既定キーを使い、空文字列で無効になります。変更・解除後は旧キーでその書式操作を実行しません。「使用默认」（既定値を使用）の後も保存が必要で、他の操作は変更しません。
- MarkLeaf 内の重複や保存・元に戻す・ソース切り替えなどの予約キーは、理由を表示して保存を拒否します。JSON で直接設定した無効・重複項目も表示して無効化し、旧キーへ暗黙に戻しません。
- 保存範囲は画面上部に表示します。既存のフォルダ設定を優先し、次にワークスペース、なければユーザー設定を使います。他の操作から継承したキーをその範囲へコピーせず、Markdown 文書も書き換えません。
- 対象は現在の MarkLeaf のレンダリング編集領域のみです。閲覧モード、検索欄、数式・図のソース欄、VS Code 標準ソースエディタでは書式キーを実行しません。IME 変換中と AltGraph の入力は従来の動作を保ちます。

67 項目の書式操作は `markleaf.insertMathInline`、`markleaf.insertMathBlock`、`markleaf.setHeading1` などの独立した VS Code コマンドとしても登録されます。連続キーなどは VS Code Keyboard Shortcuts で設定し、条件を `activeWebviewPanelId == markleaf.editor && markleaf.focus == document` に限定してください。同じ操作の MarkLeaf 側の旧キーは解除して、二重の入口を残さないようにします。

MarkLeaf メニューが表示するのは `markleaf.shortcuts` の有効な設定のみです。VS Code の公開拡張 API は解決済みの全体キーマップを公開しないため、別途設定した `keybindings.json` の上書きや、他の拡張機能・OS による横取りをすべて反映・検出することはできません。その場合は VS Code Keyboard Shortcuts で確認してください。

文書、保存、未保存状態、編集履歴は VS Code の `TextDocument` が管理します。ソース表示・横並び表示も同じ文書を共有します。連続入力の取り消しは同期単位で行い、IME 入力は変換確定後に同期します。「已同步到 VS Code」はテキストバッファへの反映を表し、ディスク保存の有無は VS Code の未保存表示で判断します。

Webview は一度に 1 件の編集を送り、バージョン確認後に蓄積した変更を送ります。自身の編集確認ではエディタを作り直しません。他の表示が文書を変えた場合、古い編集で上書きせず、未同期内容を保持して「将未同步内容打开为草稿」（未同期内容を下書きとして開く）を提供します。VS Code が下書きを開くと現在のファイルを再読み込みするので、ソース側で内容を統合してください。

各ファイルの MarkLeaf ビジュアル表示は 1 つで、標準ソースと横並びにできます。非表示のビューも未完了入力を保持します。通常の保存は同期を待ちますが、VS Code 終了時は保存処理の参加機能を省略する場合があります。閉じる前に同期を確認し、競合した内容は先に下書きとして開いてください。

## 組版と設定

「视图」（表示）の組版・設定項目から開くか、VS Code 設定で `@ext:markleaf.markleaf` を検索します。ユーザー、ワークスペース、ワークスペースフォルダの既存範囲を使用します。

| 設定群 | 主な設定 |
| --- | --- |
| 組版・配色 | `typography` は sans、serif、print、print-double、latex、retro-print、minimal、magazine、notebook の 9 種。`colorTheme` は既定で VS Code に追従し、19 種の内蔵配色も選べます。通常の文書表示も `minimal`（Web · 極簡）が既定です。文字の階層、余白、表の細部を保ち、既存のユーザー・ワークスペース設定を優先します。 |
| フォント・幅 | `fontSize`（既定 16）、`fontFamily`、`lineHeight`、`maxWidth`（既定 820）、`ignoreMaxWidth`、`zoom`。必要なフォントは本機にインストールしてください。 |
| コード・CJK | `showCodeHighlight`、数式・図ソース用の `sourceFontFamily` / `sourceFontSize`、`cjkLanguage`、`cjkAutoSpacing`。視覚的な間隔はソースへ空白を挿入しません。 |
| 表示 | `defaultMode`、`showOutline`、`focusMode`、`typewriterMode`、`showStatusBar`、`showBlockHandle`、`autoHideScrollbars`、`ctrlWheelZoom`。 |
| Markdown 編集 | `codeFence`、`emphasisMarker`、`bulletMarker`、`exitBlockOnEmptyEnter`、`useShiftEnterHardBreak`、強調変換と記号エスケープ。シリアライズ設定は実際の編集後に適用します。 |
| 画像 | `imageDirectory`、`fileImageHandling`、`useRelativeImagePaths`、`prefixImagePathsWithDot`。 |
| 書式キー | `shortcuts`。「视图 → 快捷键…」の記録画面と共通で、VS Code の MarkLeaf レンダリング編集領域のみが対象です。 |
| カスタム CSS | `customCss` に文書からの相対パスまたは絶対パスを指定します。信頼されたワークスペースのみで読み込み、CSS 変更後はエディタを再読み込みします。 |

通常の Markdown ソースのフォント・インデント・キーは VS Code 標準設定を使います。ファイル、最近使った項目、タブ、自動保存、復元、文字コード、改行、ウィンドウ配置、拡張更新も VS Code の機能を使います。共有の数式・図コントロールは VS Code の言語から既存の簡体字中国語・繁体字中国語・英語・日本語訳を選びます。出力メニュー、画面、コマンド、状態メッセージは VS Code の言語に応じて簡体字中国語・繁体字中国語・英語・日本語を使います。既存の編集メニューと書式コマンド名は引き続き中国語、その他の既存コマンド名は英語です。4 言語の文書提供は、UI 全体の翻訳完了を意味しません。

## 書式保持と提供範囲

開く・読むだけでは元ファイルを変更しません。ビジュアル編集は Markdown の解析・シリアライズを通るため、リスト記号、空行、強調などが正規化される場合があります。改行コードと既存の末尾改行は保持しますが、バイト単位の一致は保証しません。段落、見出し、リスト・タスク、引用、コード、表、画像、リンク、YAML Front Matter、脚注、数式、Mermaid、アラートが対象です。MDX、独自プラグイン構文、任意の生 HTML を厳密に保つ文書はソースで編集してください。

下線は境界が明確な `++text++` を読み取れます。内側の先頭・末尾は空白にできず、外側は英字・数字・アンダースコア・他のプラスに接続できません。`C++`、`C++17`、通常のインクリメント演算子は文字列のままです。ビジュアル編集後は `<u>…</u>` で保存し、プラスや単語内の選択との曖昧さを避けつつ、連続空白と他のインライン書式を保持します。ネイティブ版も同じ規則です。

対象はデスクトップ版 VS Code で、ブラウザ版の拡張入口はありません。リモート URI は VS Code のファイルシステム・リソース API を使用しますが、Windows、Linux、SSH/WSL や実際のクリップボード、ドラッグ、IME、キー操作は各環境での確認が必要です。ビルド、Vitest、モックホストのテストは、インストール後の UI 検証を代替しません。

PDF、HTML ファイル、縦長画像のPDF、HTML、PNG/JPG 画像、プレビュー、印刷に対応しました。ネイティブアプリのエクスポート機能は引き続き利用できます。[機能対応表（簡体字中国語）](./feature-parity.md) も参照してください。

## 開発とビルド

Node.js 22.12 以降とプロジェクト指定の pnpm を使用し、リポジトリのルートで実行します。

```bash
pnpm --dir packages/editor-web install --frozen-lockfile
pnpm --dir apps/vscode install --frozen-lockfile
pnpm build:vscode
pnpm test:editor-web
pnpm package:vscode
```

開発時は既存の VS Code を使用できます。

```bash
code --new-window --extensionDevelopmentPath="$PWD/apps/vscode" path/to/document.md
```

`packages/editor-web/src/vscode.ts` が拡張フロントエンド、`apps/vscode/src/extension.ts` が文書アダプターです。Windows/macOS は `main.ts` とネイティブホストプロトコルを使用します。拡張の出力は `apps/vscode/dist`、ネイティブフロントエンドは `packages/editor-web/dist` です。
